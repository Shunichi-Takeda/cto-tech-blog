# 自分の会議録音から「偉人の名言」を作らせたら、意外と面白かった

今回は肩の力を抜いた話です。

自分の会議録音から何気ない一言を拾い、AIに「偉人の名言」として解説させてみました。これが、思ったよりちゃんと面白い。

![会議での一言を、ロボットが真顔で羽ペンを取って解説する流れと、にやけると台無しで真顔だと名言になる、という見どころのドット絵](/images/ai-meigen-from-own-meetings/overview.png)

面白さの出どころは、AIが一切ふざけないことでした。だるい、と言っただけの一言を、マリー・キュリーの名言と同じ真剣さで解説してくる。その温度差です。

## 出てきた一本目

最初に出てきたのがこれです。

```
📜 名言
"ここはだるいですけど、重要なんですよ。"
（It is tedious, and yet — therein lies its importance.
 ─ 退屈であること、それこそが重要さの証なのである。）

👤 人物
武田 峻一（Shunichi Takeda）（生年非公開〜現在）

💡 背景・解説
日本の技術者。社内のAI活用を広める取り組みを率いた人物として知られています。
この言葉は、日々の業務を記録する作業について議論していたときに出たものです。
彼はこの作業を面倒なものだと率直に認めながらも、その価値を少しも疑いませんでした。
直後には「20年間ずっとだるいと思います」とも語っています。
退屈と重要性は両立しうると示した、彼らしい一言です。

🗓 出典: 社内の打ち合わせより
```

言った覚えはあります。言った覚えはあるのですが、こう出されると何も言い返せません。

英訳が付いているのも効いています。日本語で言っただけなのに、英語の「原文」がどこかにあるかのような顔をしている。

## 仕組みは、録音を読んで一言を選ぶだけ

やっていることは単純です。Claude Code の Skill（エージェントに渡す手順書）として書き、「名言」「今日の名言」と頼むと動くようにしています。

1. 録音デバイスのサービス（話者分離つきの文字起こしを返すもの）から、録音の一覧を取る
2. 1本を選んで、文字起こしを取る
3. 話者が自分だと確定しているセグメントだけを候補にする
4. 文脈から切り離したときに、断定的・逆説的に響く一文を選ぶ
5. 名言集のフォーマットで出す

選ぶ基準は Skill の中に書いてあります。狙い目として挙げているのは、たとえばこういう型です。

```
- 決意・胆力系:   追い込まれた状況での静かな決意として解説が書ける
- 本質喝破系:     「繋いでみてなんぼみたいなところがあるので」→ 実践主義の思想
- 達観・詠嘆系:   「しみじみのしみじみと、そう思いますね」→ 万感の境地

短く、一文で完結し、固有名詞を含まないフレーズほど名言化しやすい。
```

「繋いでみてなんぼ」は、こう解説されました。

```
📜 名言
"繋いでみてなんぼみたいなところがあるので。"
（It is only by connecting that we truly know.
 ─ 繋いでみて、初めて人は知るのである。）

💡 背景・解説
この言葉は、あるAPI基盤の構築において、設計やレビューを重ねてもなお残る
不確実性を前に発せられたものです。机上の完璧さよりも実際に動かして確かめることを
重んじる、実践主義（プラグマティズム）の精神を端的に表した言葉として、
示唆に富む一言です。
```

プラグマティズム、と言われるとそんな気もしてきます。

## 笑いを壊さないためのルール

作ってみて分かったのは、AIが少しでもふざけると途端に面白くなくなることです。解説に「（笑）」が入ったり、ツッコミを入れたりすると、ただの内輪ネタになります。

なので Skill には、真顔を守るルールを明示しています。

```
- 解説は100%真顔。茶化し・ツッコミ・「（笑）」は厳禁。ユーモアは温度差からのみ生まれる。
- Wikipediaや名言集サイトの解説文体で書く。
  「〜として知られています」「〜を体現した言葉です」「彼らしい一言です」等を使う。
- 人物の肩書は偉人の紹介文風に盛ってよい。ただし事実の範囲で。
```

肩書は盛ってよい、ただし事実の範囲で。偉人っぽさのために経歴を創作し始めると、ジョークではなく嘘になります。

もう1つ、いちばん大事なのが改変のルールです。

```
引用は実際に発した言葉そのもの。除去してよいのは次の3つだけ。
  (1) フィラー（「あの」「ええと」「まあ」）
  (2) 文字起こしの明らかな誤変換
  (3) 言い直し・反復による重複
語句の言い換え・追加・創作は禁止。
```

実在の発言だから面白いのであって、AIが名言らしく整えた瞬間に面白さが消えます。出典行を必ず付けさせているのも同じ理由です。出典を見て「これ言ったわ…」となる瞬間が、この Skill のオチになっています。

毎回同じ名言が出ないよう、実行のたびに違う録音、違う時期を選ばせています。要はガチャです。

## 録音をAIに通すことの線引き

ここは軽い話の中で、唯一まじめに書いておきたいところです。会議の録音をAIに読ませることに、引っかかりを覚える方もいると思います。

この Skill は、次の3段階で範囲を絞っています。

1. 素材は社内会議の録音に限る
2. 社内で、社内の人に向けて使う
3. 使うのは自分自身の発言だけで、同席者の発言は使わない

3つ目を機械的に守るために、話者が自分だと確定しているセグメントしか候補にしていません。文字起こしの話者分離は間違えることがあります。推測で「これは自分の発言だろう」と断定させると、他の人の発言を自分の名言として出す事故が起きるので、名前が解決されていない録音はまるごと飛ばします。

面談・面接の録音も対象から外しています。候補者のプライバシーに関わるためです。障害対応の録音は名言の宝庫なので使いますが、影響範囲や原因の詳細のような生の情報が解説に入らないことを条件にしています。

## まだ決めていないこと

同席者の発言も入れたら、たぶんもっと面白くなります。会議では、自分より他の人の方がいいことを言っている場面も多いです。

ただ、本人の同意をどう取るかを決めていないので、今は入れていません。名言にされること自体を喜ぶ人もいれば、嫌がる人もいる。そこを確かめる仕組みを作ってからにするつもりです。

## まとめ

- 何気ない一言を、AIに真顔で偉人の名言として解説させると、温度差で笑いが生まれる。
- AIが茶化すと面白くなくなる。真顔を守るルールは明示しておく。
- 引用の改変はフィラーと言い直しの除去だけ。実在の発言だから面白い。
- 録音の扱いは、社内会議・社内向け・自分の発言だけ、の3段階で絞る。話者が確定していない発言は使わない。
