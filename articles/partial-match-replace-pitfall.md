利用者が自分で語を登録できる「置換辞書」を、入力に部分一致で当てていると、1文字の登録ひとつで、その文字を含む単語が片端から別の語に書き換わることがあります。

![辞書に「P」を1文字だけ登録すると、「Payment」の頭の P に当たり、P がパイナップルに置き換わって別の語に化ける、という3場面のドット絵](/images/partial-match-replace-pitfall/overview.png)

実際に、入力のどこにも無い社名が出力に現れる、という形で表に出ました。登録した側は、略称を1つ足しただけのつもりです。

欠陥というより、部分一致の置換が持っている挙動です。ただ、知らないと原因に辿り着くまでが長い。`include?` と `gsub` で辞書を当てているコードがあるなら、登録語の最短の長さを一度数えておくと、同じ報告が来たときに当たりがつきます。

## 入力のどこにも無い社名が出てきた

最初の報告はシンプルでした。自社名を含む文を入れたら、出てきた結果に、まったく関係のない実在の社名が混ざっていた。

社名が入り込める経路は2つありました。出力の材料になった元データに紛れ込んでいたか、途中で入力が書き換えられたか。

前者は数えれば消せます。材料になったデータを読み取り専用で引き、その社名が何回出てくるかを数えました。

結果は0回でした。元データから来た線はこれで消えます。

後者で入力を書き換えうるのは、置換辞書だけです。そこで、本番の辞書をそのまま読み込み、同じ入力で置換処理だけを再計算しました。外部への書き込みも、後続の処理の呼び出しもしない、置換関数を単体で動かすだけの確認です。

化けていました。入力にあった自社名の一部が、別の社名に置き換わっていたのです。

## 1文字の登録が、すべてを書き換える

辞書には、ある社名と英字1文字を「同じ意味の語」として束ねたグループが登録されていました。略称のつもりだったのだと思います。

照合のコードを、架空の辞書で再現するとこうなります。

```ruby
# Ruby 3.2
# 架空の辞書: 1グループ = 同じ意味として扱う語の集まり
DICTIONARY = [
  ["パイナップル", "P"],    # 略称のつもりで1文字を登録
  ["見積書", "見積もり"],
]

def expand_naive(word)
  w = word.downcase
  DICTIONARY.flat_map do |group|
    terms = group.map(&:downcase)
    hit = terms.find { |t| w.include?(t) }
    next [] unless hit
    (terms - [hit]).map { |other| w.gsub(hit, other) }
  end
end

p expand_naive("Payment画面") # => ["パイナップルayment画面"]
p expand_naive("API仕様")     # => ["aパイナップルi仕様"]
p expand_naive("見積書の様式") # => ["見積もりの様式"]
```

3つ目は意図どおりの動きです。問題は1つ目と2つ目で、`include?` が「p」を含むかどうかしか見ていないため、Payment の先頭の「p」にも、API の真ん中の「p」にも当たります。そして `gsub` が、その1文字を律儀に置き換えます。

小文字に揃えてから照合しているのも効いています。大文字の「P」で登録したつもりが、入力側の小文字の「p」にも一致する。英字の1文字は、英単語や略語のほとんどに含まれます。登録した瞬間から、実質すべての英字の入力が対象になります。

厄介なのは、出力では化けた跡が見えにくいことです。実際の出力では、上の「パイナップルayment」のような不自然な形ではなく、自然な語の形に均されていました。出力だけを見ていると、置換が起きたこと自体が読み取れません。

## 置換に渡った値が、どこにも残っていなかった

原因の確定で一番困ったのは、置換に渡った語がログに残っていなかったことです。入力全体は残っていましたが、そこから切り出されて辞書に当てられた語は記録されていませんでした。

なので、再現は仮定の上に立てています。「入力がこう分割されたなら、こう化ける」という形です。

仮定が外れていたら結論も揺らぐので、照合の流れを読み直しました。すると、辞書との照合は、分割された語の前に入力全体に対しても走っていました。入力にその1文字が1つでもあれば、分割のされ方に関係なく、この置換は必ず入ります。仮定に依存しない、と確かめられたのはここです。

運が良かった、とも言えます。照合の順番が逆だったら、仮定を検証する手段がありませんでした。

置換を入れる箇所では、前後の値を1行でいいので残しておくべきでした。

```ruby
# Ruby 3.2 / Rails 7.0
expanded = expand(word)
Rails.logger.info(
  { event: "dictionary_expand", input: word, output: expanded }.to_json
) if expanded.any?
```

置換が起きたときだけ出すので、量はさほど増えません。次に同じ報告が来たら、仮定を置かずにログを引くだけで済みます。

## 仕組みで防ぐとしたら

目の前の症状は、該当の登録を辞書から外せば消えます。データ1件の変更で済み、間違っていても登録し直せば戻せます。

何を登録するかは、基本的には登録する人の判断です。それでも仕組みの側で防ぎたい場合には、いくつか選択肢があります。

| 方法 | 効くもの | 失うもの | 後戻りのコスト |
|---|---|---|---|
| A. 登録語の最小文字数を設ける | 1文字の登録による暴発 | 1文字の正当な略称が登録できない | 小さい（下限を変えるだけ） |
| B. 英数字の語は前後が英数字でないときだけ一致させる | 英字の語が単語の内側に当たる事故 | なし（日本語の語には効かない） | 小さい |
| C. 形態素解析で区切ってから照合する | 日本語の語の内側に当たる事故 | 解析器の導入と辞書の保守 | 大きい |
| D. 完全一致だけにする | 内側に当たる事故の全部 | 「見積書の様式」のような、語を含む入力への置換 | 小さいが、機能の意味が変わる |

AとBは併用できます。組むとこうなります。

```ruby
# Ruby 3.2
DICTIONARY = [
  ["パイナップル", "P"],
  ["見積書", "見積もり"],
  ["API", "エーピーアイ"],
]

MIN_LENGTH = 2

# 英数字だけの語は、前後が英数字でないときだけ一致させる
def pattern_for(term)
  if term.match?(/\A[a-z0-9]+\z/)
    /(?<![a-z0-9])#{Regexp.escape(term)}(?![a-z0-9])/
  else
    Regexp.new(Regexp.escape(term))
  end
end

def expand(word)
  w = word.downcase
  DICTIONARY.flat_map do |group|
    terms = group.map(&:downcase).select { |t| t.length >= MIN_LENGTH }
    hit = terms.find { |t| w.match?(pattern_for(t)) }
    next [] unless hit
    (terms - [hit]).map { |other| w.gsub(pattern_for(hit), other) }
  end
end

p expand("Payment画面") # => []
p expand("API仕様")     # => ["エーピーアイ仕様"]
p expand("RAPID連携")   # => []
p expand("見積書の様式") # => ["見積もりの様式"]
```

`\b` を使わずに前後読みで書いているのは、`\b` が日本語の文字も単語の構成文字として扱うためです。「API仕様」のように英字と日本語が地続きになっていると、`\b` では API の後ろに境界が立ちません。

Dは勧めません。内側に当たる事故は確実に消えますが、「見積書の様式」に「見積もり」を当てる、という辞書が本来やりたかったことまで消えます。正しいけれど、機能の意味を変えてしまう。

なお、Bは英字の語にしか効きません。日本語の1〜2文字の登録語が別の語の内側に当たる事故まで防ぐには、Cの形態素解析が要り、解析器の辞書と置換辞書の2つを保守することになります。

## 想定される反論

「登録する側が気をつければ済む話では」

基本的にはそうです。何を登録するかは、登録する人の判断です。

ただ、登録する人は、辞書が入力にどう当たるかまでは見ていません。略称を1つ足したつもりが、英字を含むほぼすべての入力に効いてしまう。そういう挙動があると、作る側も使う側も知っておいて損はありません。この記事で書きたかったのは、そこです。

## まだ決めていないこと

どこまでを登録する側に任せ、どこからを仕組みで止めるか。注意喚起で足りるのか、登録時に警告を出すくらいはすべきか、まだ線を引けていません。

## まとめ

- 置換辞書を `include?` と `gsub` で部分一致に当てていると、1文字の登録語がその文字を含むすべての単語を書き換えることがある。
- 小文字に揃えて照合していると、大文字で登録した1文字が小文字にも当たり、影響はさらに広がる。
- 原因の確定は消去法でできる。元データでの出現回数が0回なら、元データ由来の線は消せる。
- 置換の前後の値は、置換が起きたときだけでもログに残す。残っていないと、再現が仮定の上に立つ。
- 仕組みで防ぐなら、「最小文字数」と「英数字の語は前後読みで境界を見る」の組み合わせが、後戻りのコストが小さい。
