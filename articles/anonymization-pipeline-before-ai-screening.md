個人情報を含む文書をLLMに渡す場面は増えていますが、「匿名化しています」と言うだけでは意味がありません。**具体的にどう名前を検出し、どう置換し、どうやって生データを手元から出さないか**——この記事は、その仕組みそのものを解説します。題材は応募書類（PDF）のスクリーニング補助ですが、PIIを含む文書全般に応用できます。

> 本記事は個別の対象者・評価内容には一切触れず、匿名化の仕組みのみを一般化して扱います。

## LLMに渡す前に、機械的に消す

やりたいのは「PDFの職務経歴書をLLMに要約・評価補助させる」こと。ただし氏名などの個人特定情報（PII）を、プロンプト・生成物・リポジトリに残したくない。そこで、LLMに渡す前に名前を機械的にマスクする前処理スクリプトを噛ませます。

設計の要点は次の3層です。

1. **検出と置換の仕組み** — どうやって名前を見つけ、消すか
2. **検出漏れへの備え** — NERは万能ではない、という前提の設計
3. **生データを手元から出さない仕組み** — 出力先と `.gitignore`

## 「気をつける」では守れない

満たしたい条件は3つでした。

- PDFから抽出したテキストの**人名を自動で検出・マスク**したい
- 自動検出は必ず漏れる。**漏れを検知・補完できる**仕組みが要る
- 原本・中間テキストが**リポジトリやクラウドに流出しない**こと

個人情報保護は「気をつける」では守れません。目視での黒塗りは必ず漏れ、漏れたときの影響が大きい。だからこそ匿名化はコード化された仕組みにして、再現性・レビュー性・検証可能性を持たせる必要があります。

## 検出 — 日本語NERで人名を拾う

人名の検出には、日本語NLPライブラリ GiNZA（spaCyベース、`ja_ginza` モデル）を使い、固有表現抽出（NER）で `PERSON` エンティティを拾います。正規表現で「氏名っぽい文字列」を当てるより、文脈から人名を判定できるNERの方が汎用的です。

ただし実装上、2つのハマりどころがありました。

(a) 文字正規化をしないとNERが誤動作する
PDFから抽出したテキストには、CJK互換文字（例: `⼭` のような通常と異なるコードポイントの「山」）が混ざることがあります。これがNERの精度を落とすため、抽出直後に `NFKC` 正規化をかけて通常の漢字に統一します。

```python
import unicodedata
text = unicodedata.normalize("NFKC", raw_text)  # ⼭ → 山 に統一
```

(b) 長文はページ単位に分割して処理する
NERは長すぎる入力で検出漏れが増えます。そこで抽出時にページ区切り（`--- Page N ---`）を入れておき、ページ単位でNERにかけることで検出率を保ちます。

## 置換 — スペースの揺れと部分マッチ

検出した人名は、すべて `候補者X` のようなラベルに置換します。素朴に文字列置換すると、姓名間のスペース（全角・半角・無し）の揺れで取りこぼします。そこで氏名を分割し、間に `\s*` を挟んだ正規表現を組み立てます。

```python
import re

def build_name_pattern(name: str) -> re.Pattern:
    # "山田 太郎" → r"山田\s*太郎"（スペース有無・全半角を吸収）
    parts = re.split(r"[\s　]+", name.strip())
    return re.compile(r"\s*".join(re.escape(p) for p in parts))

# 長い名前から先に置換（短い部分マッチで崩れるのを防ぐ）
for name in sorted(names, key=len, reverse=True):
    text = build_name_pattern(name).sub("候補者X", text)
```

## 漏れる前提で組む

NERは万能ではありません。「自動検出は漏れる」前提で3つの保険をかけます。

- **組織名の誤検出を除外**: `株式会社` `有限会社` `Inc.` `Ltd.` などを含むエンティティは人名から除外する（会社名を人名と誤判定するケースが多い）
- **検出結果を可視化**: 検出した人名一覧を標準エラー出力に出し、**マスク漏れを目視確認**できるようにする
- **手動補完のフック**: 自動検出に加え、`--mask-name "山田 太郎"` のように**確実に消したい名前を明示指定**できるオプションを用意する

マスクはデフォルトON。無効化（`--no-mask`）はデバッグ用途に限定し、「うっかり素通し」が起きない既定にします。

## 原本を手元から出さない

匿名化と同じくらい重要なのが、原本や中間テキストをリポジトリ・クラウドに出さないことです。ここは `.gitignore` を拡張子レベルとディレクトリレベルの二重で張ります。

```gitignore
# 候補者データ（絶対除外）
*.pdf
*.docx
*.xlsx
*.csv
output/
candidates/
data/
reports/
```

拡張子で個票ファイルそのものを弾き、ディレクトリで成果物の置き場ごと弾く。どちらか一方だと「別ディレクトリに置いたPDF」「拡張子違いの中間物」が漏れます。両方張ることで、どこに置いても・どんな形式でもコミットされない状態を作ります。

## 一方通行にする

```text
[原本PDF]           ← .gitignore で除外（手元のみ）
   │ pdfplumber で抽出 → NFKC正規化 → ページ区切り付与
   ▼
[生テキスト(PIIあり)] ← .gitignore 対象ディレクトリのみ
   │ GiNZA でNER → 組織名除外 → ラベル置換（+手動補完）
   ▼
[匿名化済みテキスト]  ← これだけをLLMに渡す
```

生PIIがLLMに到達する経路を作らず、LLMの入力は必ず匿名化済みテキスト、という一方通行にするのが肝です。

## 効いたのは順序だった

- 「匿名化しています」は主張ではなく**実装で示す**もの。検出手法・置換規則・除外フィルタ・出力先ルールまで具体化して初めて守れる。
- NERは強力だが漏れる前提で、**可視化と手動補完のフック**を必ず用意する。
- 前処理（正規化）を怠るとNERが崩れる。**抽出→正規化→NERの順序**が効く。
- この仕組みは採用に限らず、問い合わせ・契約書など**PIIを含む文書をLLMに渡す全場面**に一般化できる。

## どこまでやるかを決める

匿名化は、追い込もうと思えばいくらでも追い込めます。だから先に「どこで止めるか」を決めました。

検討して採らなかった案が2つあります。

正規表現だけで済ませる案は、早い段階で外しました。人名は種類が膨大で、列挙で当てにいく方法が成立しません。姓と名の組み合わせを網羅する現実的な手段がない以上、文脈から判定できるNERのほうが筋が良いと判断しています。

クラウドのPII検出APIを使う案も見送りました。精度は上がりますが、通す文書の量に対してコストが見合いません。そして、精度を上げること自体にもコストがかかります。完璧を目指すほど工数が伸びるので、どこかで線を引く必要がありました。

線を引けたのは、リスクの大きさを見積もったからです。この処理は採用に関する情報のやり取りの中で動いていて、仮に人名が1つ残ったとしても、それが即座に漏洩になるわけではありません。危ないのは、それをレポートとして別の場所に残してしまうことです。そこを減らすのが目的であって、検出率を1に近づけること自体が目的ではない。

## まだ決めていないこと

取りこぼしを継続的に検知する仕組みがありません。

いまは、レポートを出して終わりではなく自分で内容を読むので、その時点で取りこぼしはある程度拾えています。拾ったら次回以降の改善に回す、という手動のループです。

これで回っているうちは、精度そのものを追い込む予定はありません。不満が出るか、無駄な工数が発生してから、改めて考えることにしています。仕組みを先に作っても、動かす頻度が低ければ結局腐るからです。

## 想定される反論

「検出率を上げないと意味がないのでは」

意味がないとは考えていません。ここで守りたいのは、検出率という数字ではなく、生のPIIが残り続ける場所を作らないことです。

前の節に書いたとおり、危ないのは人名が1つ残ることそのものより、それがレポートとして別の場所に蓄積されることです。生成物に混ざる量を減らし、混ざった場合に気づける状態を作れば、目的は達成できます。検出率を1に近づける作業は、その先の追い込みであって、入口の条件ではありません。

「取りこぼしの検知を仕組みにしないのは無責任では」

仕組みにできていないのは事実です。いまは、出したレポートを自分で読む工程が実質のチェックになっています。

これで足りていると考えているのではなく、**足りなくなる合図が出るまでは作らない**という判断です。検知の仕組みも、動かす頻度が低ければ腐ります。運用に乗せた仕組みが腐った状態で残っているほうが、無いよりたちが悪い。

「そもそもPIIをLLMに渡すべきではないのでは」

渡していません。LLMに入るのは匿名化済みテキストだけで、生のPIIが到達する経路を作らない設計にしています。前段の抽出と匿名化は手元で完結し、原本と中間テキストはリポジトリにもクラウドにも出しません。

判断したのは「渡すか渡さないか」ではなく、「渡すものをどう作るか」です。

## まとめ

- 名前の検出は **日本語NER（GiNZA）** で行い、NFKC正規化・ページ分割で精度を保つ。
- 置換は**スペース揺れを吸収する正規表現＋長い名前優先**、組織名は除外し、検出一覧を可視化して**手動補完**できるようにする。
- 原本・中間物は**拡張子＋ディレクトリの二重 `.gitignore`** で手元に留め、LLMには**匿名化済みテキストのみ**を渡す一方通行にする。
